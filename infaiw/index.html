[ agent harness · daemon-first ]

Delegate the work. Keep the wheel.

infaiw is an agent harness that works with you, not around you. It runs as a background service: hand off a task, close the terminal, and come back to a durable timeline of everything it did, with every consequential step waiting for your approval.

[ 01 / the sidecar loop ]

Subagents that can't
just declare victory.

Agents love to say "done". A sidecar is a delegated subagent whose "done" doesn't count until a script written by its parent exits 0, within a turn budget the parent picked.

The parent delegates over ISAC, the engine creates the sidecar, the sidecar works and runs its own acceptance script until it passes or the turn budget runs out, and the engine relays the result back to the parent's mailbox.

1

Delegate

The parent hands off a task, a bash acceptance script that defines "done", and a budget of 20, 40 or 100 turns. You see all three before you approve the delegation.

2

Gate

Each time the sidecar claims it's finished, its own loop runs the script. If it fails, the script's output goes back into its conversation and the work continues.

3

Report

The parent gets the answer marked pass or fail, or "max iterations reached" if the budget ran out. Every attempt stays on the timeline.

exit 0

The parent decides what "done" means, not the sidecar. The verdict is a script's exit status, not the model grading its own work.

20·40·100

Every sidecar has a budget. When it runs out, the sidecar stops and reports "max iterations reached" instead of looping forever on your tokens.

any model

The gate is bash, so it doesn't care which model you use. DeepSeek, OpenAI Codex or Claude Code: a sidecar runs on its parent's model, and the gate works the same way on all of them.

a real run

The parent gets
a checked answer.

A billing integration review was handed to a sidecar. When its answer reached the parent session, it was already marked [acceptance_script success]: the script had passed before the result was delivered. The parent reads findings, not promises.

sidecar_loop · completed · 96 probes · report written · production files untouched

Inside the sidecar. Its last answer, then the verdict from its own acceptance check. Only after that does the session flip to completed and report back to its parent.

The script, on the record. ctrl+d on the sidecar shows the exact acceptance script it was created with. Every check echoes why it failed, so a failure tells the sidecar what to fix.

A real session: one parent reviewing a change through six sidecar loops, three of them paused on approvals.

[ 04 / on board ]

Built for long-running work.

The things you will notice first, then everything else.

01

Branch,
don't restart.

Forty minutes in, the agent took a wrong turn. Open the timeline, pick any event and branch from there. The first attempt stays on its own branch; nothing is thrown away, and you can search the whole history.

/timeline · ↑/↓ move · / search · ⏎ branch · ⎇ marks a fork

02

Approvals
on your terms.

Every tool is allow, human or deny. Reads just run. A write, an edit or a bash script stops and shows you exactly what it will do, then waits, even if you closed the window hours ago. One mcp_* line covers every MCP tool. Save a named policy and pick one per session; the badge shows which one is active.

Approve · Deny · Deny With Reason · ←/→ choose · ⏎ answer · ctrl+g collapse

default policyallow read · list · glob · grep · git_status · skills · checklist human write · edit · bash · web · sidecars · mcp_*

03

Know where
the tokens went.

One key shows the session's tree of sidecars and how each one ended, how full the context is, and what the last turn spent. In this session 99% of a 297k prompt came from cache. It also lists every tool, skill and MCP server that's loaded. No guessing about cost.

ctrl+d session stats · ctrl+o all sessions

04

Share the
whole story.

One command turns a session into a single HTML file: every sidecar, every branch and every tool call, filterable and collapsible, with acceptance results marked. Send it to a reviewer, attach it to the PR, or keep it as the record of how a change was made. No account and no server needed.

/report export the full timeline as HTML

05

It remembers
why.

Every checklist item has a title and a description of what you actually asked for. After compaction, or hours into a task, the agent re-reads the goal and not just its last step. A sidecar's checklist comes back with its answer, and the session tree shows which sidecars finished and which ran out of budget.

ctrl+d checklist · sidecar tree · context · last turn

06

Switch models
mid-session.

Plan with Claude Code, implement with OpenAI Codex, review with DeepSeek, or use a model you host yourself on any OpenAI-compatible endpoint. The session, its timeline and its approvals stay the same; only the model changes. One system prompt works for all of them, and provider catalogs refresh hourly without a restart.

07

Add an MCP server
without editing JSON.

A short form: remote URL or local command, a name, and whether it needs OAuth. If it does, infaiw opens the browser login for you. Its prompts show up as slash commands, its questions come to you, and one mcp_* policy line covers every tool it adds.

infaiw mcp add · edit · refresh · remove, or from the TUI

08

Scriptable
from the shell.

Policies, MCP servers and provider logins are subcommands too, so you can set up a new machine from a script. The TUI attaches to any daemon by host and port, and resumes any saved session by its id.

hitl_policy · mcp · provider · server · --session <uuid> · --host --port

09

Stored like git,
not like a chat log.

Every session is an append-only timeline of events, each pointing to its parent. HEAD marks the active branch, an index records where each event lives, history is split into chunks, and large records sit in content-addressed blobs that load only when needed. Opening, listing or branching a session reads only what it has to.

Compaction builds on the same timeline. At 80% of the context window, the last four messages stay word for word. Everything older is summarised together with the previous summary and the task checklist, and the summary is saved on the timeline as its own event with the originals kept. You can stop worrying about the context going bad.

10

Hours of history,
still instant.

Only the part of the transcript on screen, plus a buffer above and below, is drawn, in blocks cached for each terminal width. A session with thousands of events opens, scrolls and resizes in constant time. A resize keeps you on the block you were reading, and live output only follows along when you're already at the bottom.
